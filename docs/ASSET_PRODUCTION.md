# Визуальные ресурсы Auralis: готовая система и недостающий арт

Текущий игровой персонаж — временный суставной векторный rig. Поддержаны разные классовые оружия, восемь направлений, движение/ожидание/атака, удар щитом на третьем ударе паладина, короткая реакция на урон и связная поза падения. Это не заменяет окончательную художественную анимацию. Финальные персонажные спрайты пока отсутствуют; никакие тысячи одинаковых кадров не создавались ради счётчика.

## Подключение настоящего атласа

`js/assets/manifest.js` — единственное место регистрации. `queueAssets` загружает изображения, sprite sheets и Phaser JSON atlases. После загрузки `createAssetAnimations` регистрирует направления. `HeroRig` автоматически переключится на `SpriteAnimator`, если в `characters[classId]` есть корректный загруженный атлас с состояниями; при отсутствии файла остаётся рабочая программная графика.

Пример записи (пути должны указывать на реально добавленные файлы):

```js
characters: {
 warrior: {
  type: 'atlas',
  url: './assets/sprites/characters/warrior/warrior.png',
  atlasURL: './assets/sprites/characters/warrior/warrior.json',
  originX: .5, originY: .92, scale: 1,
  states: {
   idle: { frameRate: 6, repeat: -1, directions: {
    e: ['idle/e/0','idle/e/1'], se: ['idle/se/0','idle/se/1'],
    s: ['idle/s/0','idle/s/1'], sw: ['idle/sw/0','idle/sw/1'],
    w: ['idle/w/0','idle/w/1'], nw: ['idle/nw/0','idle/nw/1'],
    n: ['idle/n/0','idle/n/1'], ne: ['idle/ne/0','idle/ne/1']
   } }
  }
 }
}
```

В атласе требуется добавить состояния `run`, `attack`, `special`, `hurt`, `death` с теми же восемью направлениями. Для `hurt`, `death`, `attack`, `special` по умолчанию `repeat:0`; idle/run повторяются. Для sprite sheet используйте `type:'spritesheet'`, `frameWidth`/`frameHeight`, а списки `directions` содержат числовые индексы кадров. Ключи ресурсов должны быть уникальны между категориями.

## Blender / Python-производство

1. Согласовать единый масштаб, простую стартовую одежду и силуэты шести классов; камера ортографическая изометрическая, прозрачный фон, свет во всех клипах одинаковый.
2. Поставить origin в точку между стопами. Начальный размер кадра128×160 или192×224, без обрезки оружия/эффектов; подобрать один масштаб в игре и зафиксировать его.
3. Рендерить восемь направлений через45° с неподвижной камерой/поворотом модели, одинаковые кадры-анкорные точки во всех состояниях. Оружие и щит крепить к костям кистей, не зеркалить оружейную руку.
4. Python-экспортёр Blender должен обходить классы, action-клипы и направления, выдавать PNG и metadata `{state,direction,frame,pivot,weaponSocket}`. Номер impact-кадра согласовать с AttackCycle, а не наносить урон по произвольному красивому кадру.
5. Упаковать кадры Phaser JSON atlas инструментом упаковки; ограничивать страницы2048×2048 и тестировать расход памяти Android. Не объединять весь мир в один огромный атлас.
6. Перепроверить загрузку, все направления, переходы состояния, попадание, смерть и визуализацию экипировки в Chromium и на Android. Затем заменить отдельный программный fallback для класса.

## Точный список художественного производства

- Шесть персонажей: idle/run/attack/special/hurt/death, восемь направлений, настоящий гном-канонир; слои предметов девяти слотов или наборы совместимых костюмных слоёв.
- Десять обычных семейств существ, каждый с idle/move/attack/hurt/death; отдельные выразительные силуэты мини-боссов/мировых боссов и dungeon-боссов. Текущие векторные силуэты — временные.
- Три региональных набора окружения: деревья/скалы/растения/дороги/дома/реки/мосты/руины/входы в подземелья. Нужны изометрические pivots и корректные collision-контуры.
- Анимационные эффекты всех30 навыков: попадание/полёт/площадь/щит/лечение/яд/ледяной статус; текущие круги/снаряды не считаются окончательным VFX.
- Портреты шести классов и NPC; единые значки ресурсов, торговли, карты и экипировки.

Готово сейчас:30 различных безопасных SVG-значков навыков в `js/assets/skillIcons.js`; они не используют случайные Unicode-глифы. HUD и панели навыков отображают `skill.iconSvg`. Окончательные спрайты/атласы нельзя отмечать TESTED до появления реальных файлов и проверки их на целевом устройстве.

## Переходы клипов и точки оружия

Runtime различает `attack` и `special`; новый удар перезапускает одноразовый клип даже без промежуточного idle. Death/hurt не перезапускаются каждый кадр. Если special отсутствует в реальном наборе, используется attack соответствующего направления.

Для точного вылета снаряда добавьте `weaponSocket: {x:12,y:-36}` (координаты относительно origin героя) и, при необходимости, `weaponSockets: {'cast/e/1': {x:18,y:-42}}` для отдельных имён кадров. SpriteAnimator переводит socket через текущую мировую матрицу. Без socket используется безопасная стартовая точка снаряда героя; отсутствие программного sword-узла не вызывает ошибку. Это проверка инфраструктуры, а не наличие окончательных атласов.
