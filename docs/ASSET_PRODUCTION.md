# Визуальные ресурсы Auralis

Обновлено 13 ноября 2026. В активных реестрах 79 настоящих PNG/JSON атласов: шесть нейтральных баз игровых классов, 23 обычных вида монстров, шесть паков с 21 NPC, 18 открытых и 26 подземельных боссов. Каждый герой, вид и босс имеет 32 кадра: восемь направлений × idle / два шага / attack. NPC имеют 168 направленных кадров в шести общих паках. Всего активно 2504 нарисованных кадра.

Шесть прежних одетых атласов героев сохранены отдельно: всего в Git 85 актёрных PNG. Все 24 контрольные суммы прежних PNG/JSON героев и NPC неизменны. Проверка — `characterBaseBodies.test.mjs`, манифест — [PRESERVED_CHARACTER_ASSETS.json](art/PRESERVED_CHARACTER_ASSETS.json). Ни прежние герои, ни NPC не удалены и не перезаписаны.

## Базовые тела и независимая экипировка

Новые PNG/JSON в `assets/actors/heroes/base/` показывают взрослых персонажей в непрозрачном нейтральном сером белье, босиком и с пустыми руками. На теле нет оружия, щита, шлема, брони или украшений. Все шесть классов подключены через `heroBodies.js` и `ACTOR_ART`; `LEGACY_HERO_ART` сохраняет прежние образы как референсы. Пропорции короткого широкого гнома-канонира сохранены.

`CharacterEquipmentLayers` отображает девять независимых слотов процедурными слоями. Оружие рисуется полностью отдельно; пустой слот ничего не рисует. Замена, снятие и редкость меняют соответствующий слой. Снаряды используют фактическую мировую матрицу оружия, без оружия — точку кисти. Экранное направление не проходит повторное изометрическое сжатие.

Покадровые точки головы, кистей и корпуса пока оценочные с поддержкой измеренных переопределений. Их художественная калибровка, глубина дальних рук и независимо нарисованные слои предметов ещё требуются. Все 21 NPC пока остаются цельными одетыми образами: переход NPC на модульные нейтральные тела не завершён. Для новых баз NPC действует тот же запрет на встроенную экипировку. Подробная оценка — [CHARACTER_LAYERING.md](CHARACTER_LAYERING.md).

## Подключение и память

Главные реестры: `js/assets/actorArt.js`, `heroBodies.js`, `monsterArt.js`, `npcArt.js`, `bossArt.js`. `HeroRig`, `MonsterSystem` и `ChunkWorld/PaintedNpc` реально создают `PaintedActor` / `PaintedNpc`. Выбранный герой предварительно загружается отдельно; весь набор моделей одновременно не загружается.

`ActorTextureCache` выдаёт ссылки с подсчётом владельцев, загружает только выбранного героя и актёров текущих чанков, освобождает текстуру после последнего владельца и обрабатывает позднее завершение загрузки. Новые слои экипировки уничтожаются вместе с контейнером персонажа. Старые шесть атласов героев остаются в репозитории, но не занимают память рядом с новыми базами.

`register-boss-art.mjs` читает PNG без изменения пикселей, проверяет прозрачные границы и все 32 кадра, вычисляет опорные точки ног отдельно для каждого банка. В реестр попадают только полные committed PNG/JSON пары. Имена, HP и уровни имеют отдельную жизненную логику и не являются частью картинки.

Шесть состояний работают: `idle/run/attack/special/hurt/death`. Нарисованных банков четыре: `idle`, `run-a`, `run-b`, `attack`. Специальные действия используют атакующую позу и настоящие игровые VFX; hurt/death дополняются recoil/tint/fall/fade. Это не шесть независимо нарисованных клипов. Отдельные плавные покадровые переходы остаются художественной работой.

## Резервный API многокадровых анимаций

`manifest.js` / `SpriteAnimator` сохранены для будущих полноценных многокадровых наборов. Текущие герои используют перечисленные выше реестры. Пустой optional `characters` manifest не означает отсутствие подключённого арта.

Пример записи для реально добавленного набора:

```js
characters: {
 warrior: {
  type: 'atlas',
  url: './assets/sprites/characters/warrior/warrior.png',
  atlasURL: './assets/sprites/characters/warrior/warrior.json',
  originX: .5, originY: .92, scale: 1,
  states: {
   idle: { frameRate: 6, repeat: -1, directions: {
    e: ['idle/e/0','idle/e/1'], se: ['idle/se/0','idle/se/1'],
    s: ['idle/s/0','idle/s/1'], sw: ['idle/sw/0','idle/sw/1'],
    w: ['idle/w/0','idle/w/1'], nw: ['idle/nw/0','idle/nw/1'],
    n: ['idle/n/0','idle/n/1'], ne: ['idle/ne/0','idle/ne/1']
   } }
  }
 }
}
```

Добавить `run/attack/special/hurt/death` с теми же направлениями. Одноразовые действия используют `repeat: 0`; idle/run повторяются. Для spritesheet нужны `frameWidth/frameHeight` и числовые индексы. Ключи ресурсов уникальны между категориями. Новые character atlases обязаны соблюдать контракт нейтрального тела и отдельной экипировки.

## Рекомендации для Blender / Python-производства

1. Зафиксировать анатомию, нейтральное непрозрачное бельё и разные силуэты классов. Отдельные одежда, броня, оружие и щиты не входят в рендер базового тела. Камера ортографическая изометрическая, фон прозрачный, свет одинаковый.
2. Origin поставить между стопами. Согласовать размер кадра и масштаб в игре; не обрезать руки или будущие предметы. Текущие принятые атласы используют ячейки 192×256.
3. Рендерить восемь направлений через 45°, сохраняя опорные точки. Правую и левую кисти не менять зеркальным отражением. Для отдельного оружия экспортировать точки крепления и направление хвата каждой позы.
4. Экспортировать PNG и metadata `{state,direction,frame,pivot,weaponSocket}`. Impact согласовать с `AttackCycle`; рендер не должен менять расчёт урона.
5. Упаковывать страницы не больше 2048×2048 и проверять реальную память Android. Не объединять мир в один огромный атлас.
6. Проверять загрузку, все направления, состояния, предметные слои и освобождение ресурсов в Chromium и на Android. Сохранять прежние готовые файлы при добавлении новых.
