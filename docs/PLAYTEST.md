# Игровая проверка и ограничения

Актуальные результаты автоматических запусков и CI: [TEST_RESULTS.md](TEST_RESULTS.md). Числа контента/статусы: [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md). Этот документ описывает ручную приёмку; незапущенные пункты ниже не являются пройденными тестами.

## Автоматизация

`npm run check`, `npm test`, `npm run test:browser`. Для системного браузера: `CHROMIUM_PATH=/usr/bin/chromium npm run test:browser`. Playwright-сценарии поднимают локальный сервер и закрывают его/браузер после выполнения. Снимки — `work/browser/`.

Smoke использует UI и настоящие CDP multitouch-события. Расширенные suites перебирают все254лагеря/1145spawn,21NPC,18открытых боссов,36dungeon-вариантов,104quest и30skill через реальные системы. Для воспроизводимости уровни/ресурсы/координаты и часть ударов задаются fixtures. Это проверяет связь контента с runtime, награды/сохранения/проходимость, но не заменяет ручной бой и приключение1–42.

CI на `ubuntu-24.04` берёт предустановленный Google Chrome через `CHROMIUM_PATH`. Не возвращать `playwright install --with-deps chromium`: прежнее падение PR#1 возникало до тестов из-за DNS Ubuntu APT-зеркал. Ошибки самих браузерных проверок должны оставаться обязательными, не игнорироваться.

## Ручной маршрут без fixtures

1. Создать нового героя, проверить простую стартовую одежду и точное имя/класс. Поговорить с Мирой, принять поручение, найти волков по карте и победить обычной атакой. Удерживать атаку одним пальцем и двигаться другим; отпускать каждый палец за пределами кнопки.
2. Получить и сдать награду, продать добычу/купить зелья, распределить атрибуты, изучить навык и назначить в один из4слотов. Проверить MP/cooldown, недостаток MP, отсутствие допустимой цели, зелья и уведомление о покупке3с.
3. Надеть подходящую вещь, осмотреть изменившуюся часть персонажа, сравнение и ограничения уровня/класса. Перенести предмет через NPC в shared storage, открыть другого героя и забрать его. Убедиться в независимости трёх save slots.
4. Достичь5уровня обычными заданиями/боями и войти в dungeon№1 у1820,1780. Проверить все3сложности, предупреждения босса, видимость за стенами, награды и выход. Погибнуть и проверить возврат ко входу с40%HP/MP.
5. Пройти основные дороги к другим поселениям, найти NPC по карте/координатам задания, завершить разговор/доставку/сбор/исследование. Перейти в соседний регион доступным порталом. В лесу отдельно проверить вход/выход арены.
6. Сохраниться далеко от старта и перезагрузить страницу. Сравнить регион/координаты/задания/экипировку/слоты/зелья/золото/dungeon progress. Проверить смерть босса до/после выгрузки чанка/reload и отсутствие повторной награды на cooldown.
7. Экспортировать JSON через окно резервов, импортировать его в выбранный слот с подтверждением. Скачать before-import резерв, проверить восстановление предыдущего героя. Повреждённый/будущий формат должен отклоняться без потери данных. Не очищать localStorage во время приёмки обновления.
8. Повторить ключевые панели/информацию/ошибки на EN/ES, закрывать каждую панель собственными кнопками, проверить внутреннюю прокрутку, паузу и возврат управления.

## Физический Android: ещё не выполнено

Открыть отдельную HTTPS master-версию без установки программ. До выпуска URL фиксируется в TEST_RESULTS, старый alpha-test не заменяется. Для переноса героя между адресами использовать экспорт/импорт: localStorage принадлежит origin.

Проверить несколько landscape-размеров и системные safe areas,2–3пальца одновременно, отпускание вне экрана, системные жесты, поворот в portrait и обратно, сворачивание/восстановление, сон вкладки и загрузку после выгрузки браузером. На подходящем игровом Android измерить15–30минут боя/переходов: FPS/frame time, память и нагрев. Зафиксировать модель/ОС/браузер, длительность и условия; без этого цель60FPS не считается достигнутой.

## Границы текущих доказательств

Прохождение по всему миру с fixtures подтверждает наличие/связь runtime-контента, но не художественное качество, полную достижимость без телепортации каждого участка или ручной баланс1–42. Временные rig/силуэты/круги VFX не равны финальным спрайтам; список отсутствующего арта в [ASSET_PRODUCTION.md](ASSET_PRODUCTION.md). Объектные лимиты streaming не равны доказательству отсутствия утечек.

Старые alpha-preview замеры SwiftShader показывали около30FPS после кэширования на программном GPU. Они относятся к прежней зоне2400×2400 и не являются benchmark нового мира или физического Android. Новый замер должен указывать конкретный snapshot и нагрузку.
