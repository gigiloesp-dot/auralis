## Текущая незавершённая проверка

1. Закончить регрессии последних классовых механик: реальная наземная ловушка лучника (срабатывание, срок действия), заряды защиты и тики ауры паладина, ответ защиты воина/канонира, потребление яда ассасина. Старый тест всех навыков не учитывал `system.traps` и падал на `archer_1`; подтвердить поведение, не удалять проверку результата.
2. Добавить `browser-classes.cjs` в общий `npm run test:browser`, повторить все 7 suites после последних правок. Команды: `npm run check`, `npm test`, `CHROMIUM_PATH=/usr/bin/chromium npm run test:browser`. Обновить точные числа и проверенный SHA в TEST_RESULTS.
3. Зафиксировать общую интеграцию отдельным коммитом, отправить только рабочую ветку и дождаться CI в [PR #2](https://github.com/gigiloesp-dot/auralis/pull/2). Изучить логи при ошибке, исправить и повторить.
4. Создать новую отдельную публичную HTTPS-публикацию из этого проверенного коммита. Прежний `https://auralis-alpha-test.alertpine18.chatgpt.site` не заменять. Проверить свежим браузером фактически загруженные source/build и запуск новой игры, touch, save/reload, региональный runtime. Записать точный URL, SHA и доказательства.

## Следующие независимые задачи качества

- Провести финальный аудит требований MASTER_SPEC и устранить найденные расхождения runtime. Не отмечать пункты готовыми только по длине каталогов.
- Проверить долгую сессию в браузере: повторные переходы всех карт/подземелий/арены, закрытие панелей, reload/backup, стабилизация числа текстур/объектов и JS heap после GC. Зафиксировать длительность, условия GPU и наблюдаемые ограничения.
- Пройти обычный игровой маршрут без level/resource fixtures: новый герой → первые задания/покупка → dungeon5 → соседние поселения/регион. Численные тесты бюджета 1–42 уже есть; они не заменяют ручное исследование темпа, цен, сложности и навигации.
- Проверить непокрытые сочетания экипировки, статусов, навыков и кнопок на малых экранах; редакторски вычитать RU/EN/ES, особенно новые точные описания классовых эффектов.
- Для каждого найденного дефекта: реальное исправление, соответствующий тест, отдельный коммит и новый общий результат проверок.

## Внешние препятствия, не скрывать

1. **Окончательный арт.** Программная изометрическая графика работоспособна, но не равна финальному художественному набору. В [ASSET_PRODUCTION.md](ASSET_PRODUCTION.md) перечислены персонажи/монстры/окружение/VFX/портреты и процесс Blender/Python. Подключать только реальные sprite sheets / atlases через `js/assets/manifest.js`; не генерировать тысячи одинаковых кадров для счётчика.
2. **Физический Android.** Проверить два и более пальца, landscape/portrait, сворачивание браузера, аудио/системные жесты (если применимо), save/reload и 15–30 минут игры. Измерить FPS, нагрев, память и поведение после сна вкладки. Пока устройства нет, 60 FPS и полная мобильная приёмка имеют статус BLOCKED.

## Важные правила продолжения

- Все три большие карты, 254 лагеря / 1145 обычных врагов, 7 поселений / 21 NPC, 18 открытых боссов, 12 dungeon / 36 variants и 104 quests уже интегрированы. Не возвращаться к старому плану «создать ChunkWorld/первое подземелье»: он устарел.
- Не менять старые save keys, не очищать localStorage и не ломать pending journal shared storage. Импорт должен сохранять before-import резерв и не перезаписывать нового героя завершающим save старой сцены.
- Проверять cooldown и смерть после reload/выгрузки. Сохранение при паузе пересчитывает cooldown относительно остановленного simulation clock; новый world runtime сохраняет идентичность live hero.
- Fixtures в тестах указываются явно; прохождение с телепортацией и летальными hit-вызовами не называть ручной победой/полным прохождением 1–42.
- При ограничении среды сохранить весь доступный результат в Git, обновить эти документы и указать следующую конкретную незавершённую задачу. Итоговая сдача невозможна без честного списка оставшегося.
